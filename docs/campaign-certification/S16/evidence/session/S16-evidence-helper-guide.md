# S16 evidence helper handoff

These helpers have not been executed. Both default to read-only checks; only an explicit `--apply` writes. The publisher refuses missing, changed or failed gate evidence. It writes only S16 README/manifest and the two pathway files, stops after S16, awards bounded G3 and leaves CP1 unearned. It does not run Cargo, Git, a server or the campaign.

1. Copy `S16-publication-config.example.json` to `S16-publication-config.json`, set the actual final runtime pin and `proof_label`, and fill actual final screenshot inspection findings. `proof_label: final3` expands all ordinary native/browser/Linux proof defaults and `evidence/S16-fixture-final3/manifest.json`. Set `linux_runner: run-s16-linux-final3.py` to bind the final Linux runner. Any individual path may be overridden. No earlier-candidate pass is accepted as a substitute for final qualification.
2. Prepare `S16-evidence-selection.json` as an array of `{ "source": "absolute existing file or directory", "name": "unique relative logical destination" }`. Directory entries retain every file recursively; select files individually where an executable must be excluded. Names must not overlap. Include the complete sources listed below. Keep collector/publisher bytes frozen after collection because they are retained by exact SHA-256.
3. Root runs `python collect-s16-evidence.py S16-evidence-selection.json`, inspects the plan, then runs the same command with `--apply`. It creates only `integration/docs/campaign-certification/S16/evidence` (and the new S16 parent if needed). The destination must not already exist. Files above 1 MiB use lossless gzip, and encoded files above 40 MiB split into numbered parts. The inventory verifies every original and reconstructed byte.
4. Root runs `python publish-s16-closure.py S16-publication-config.json`, inspects the four proposed document changes, then runs the same command with `--apply` only after every proof and actual review has passed. No completion is recorded by the dry run.

## Review launch record contract

Default `review_stage` is `continued`; the browser restores `defense_flown` before Save/Load/Continue. The record uses the S15 structure: `url`, `directory`, `runtime_revision`, `executable_sha256`, `build.revision`, `player`, `date`, `save_copy: {source, copy, sha256}`, `native_verification: {canonical_sha256, bytes, ignored_paths: [], exact_bytes_match_final_browser: true, worker_sha256}`, `evidence: [{path, sha256}, {path, sha256}]` linking the final binary proof and browser result, and `required_outcomes` equal to the browser result. The copied executable is `directory/spheres-web.exe`, and its native audit is `directory/native-verification/copied-save.json`. Optional `review_stage` and `review_source_save` overrides must still bind an actual retained stage and exact copied bytes.

The publisher verifies all observed reports against raw stage saves and the native comparison manifest, ordinary protected command identities, imports/refusal, paid fighter and missile delivery, reconciled aircraft holdings, funded restore and history, actual map readings and fighter canvas inspection. Counts come from final logs and actual fixture steps. It does not claim a new performance gate, finished S18 artwork, independent human testing, autonomous AI or a complete 1990–2035 campaign.
