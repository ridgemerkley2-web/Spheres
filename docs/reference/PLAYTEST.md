# SPHERES 0.6 — first campaign playtest

Use an isolated campaign and record its About version/revision, nation, seed,
viewport and date. Start paused. Do not coach the participant unless blocked;
record the point where help was required. **About → Record playtest feedback**
downloads notes locally and sends nothing automatically.

## Tasks (about 30–45 minutes)

1. Find the home country and one named province. Explain what provincial GDP is
   and which figures are estimates. Repeat with a narrow screen and keyboard.
2. Open Advisor. Review the first budget, explain its full-use funding gap and
   interest, enact it, then compare authorized and actual spending.
3. Select one useful project. Identify its ministry, prerequisites, missing inputs,
   supplier/route and ETA. Obtain inputs, advance, and explain the difference
   between ordered, in transit, delivered, construction and operating output.
4. Use Research list to find an available discovery. Explain its payoff, calendar
   gate, prerequisite and funding estimate. Inspect focus cost before changing it.
5. Open Decisions. Explain an offer's deadline and consequence. Change a standing
   policy only deliberately. Select a peaceful aim and explain its blockers.
6. Open military operations. Explain national reserves and the shared overseas
   limit. A rhetoric-only ally should not display invented combat deployment.
7. Save to a named slot, advance several days, load it, and confirm date and
   Chronicle continuity. Reload the browser and distinguish Continue from Load.
8. Record one confusing consequence or interaction and whether the interface
   supplied a useful next action.

## Record evidence

For each task record success without help, elapsed time, wrong turns, the exact
label/screen that caused confusion and what the participant expected. Note
keyboard focus, narrow-screen overflow, inability to distinguish available and
locked actions, and whether a consequence matched the displayed quote. Keep
screenshots free of unrelated personal information.

Start with five independent participants covering small, resource-dependent and
large economies; use findings to fix observed usability failures, not as a
statistical estimate of all players. Repeat changed tasks with fresh players.
Balance needs separate longer campaigns and simulation samples. Do not send
invitations or upload feedback without the user's authorization.

## Acceptance observations

The player can complete one budget → input → project → operating output chain,
explain the main cost and delay, find a named province, choose a discovery and
resume a saved campaign without source-code assistance. Failures become concrete
issues with a build identity, reproduction and expected behavior. Passing this
small protocol is not a complete accessibility or historical accuracy claim.
